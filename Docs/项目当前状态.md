## 二、RTOS架构

**8个业务Task + 1个看门狗Task**：`Task_FlightCtrl`（osPriorityRealtime7）、`Task_RC_Link`、`Task_Nav`、`Task_Blackbox`、`Task_Telemetry`、`Task_PowerMonit`、`Task_Indicator`、`Task_IwdgFeed`

> 无`Task_IMU2_RDD`——双IMU冗余判定是`Task_FlightCtrl`内部直接调用`ImuRedundancy_Update()`，不拆独立Task（拆出去会引入不必要的任务切换延迟，抵消实时性收益）。

**Queue/Mailbox**：
- `BlackboxLogQueue`（Static，深度24，`Blackbox_Frame_t`）
- `RCChannelMailbox`（深度1+覆盖式写入，`RCChannelData_t`，类型定义归属`bsp_elrs.h`）
- `NavStateMailbox`（深度1+覆盖式写入，`NavState_t`）
- `MagDataMailbox`（深度1+覆盖式写入，`MagData_t`）
- `IndicatorEventQueue`（深度8，`IndicatorEvent_t`）
- `NavCommandQueue`（深度4，`NavCommand_t`）

覆盖式写入统一按`osMessageQueueGetSpace`查满→满了先`Get`丢弃旧值→再`Put`实现（CMSIS-RTOS2无原生`xQueueOverwrite`）。

**Event**：`SystemReadyEventGroup`，五个bit，ARM解锁前必须全部置位：

```c
SYSREADY_BIT_HOME_VALID      // Task_Nav置位
SYSREADY_BIT_MAG_OK          // Task_Nav置位
SYSREADY_BIT_VOLTAGE_OK      // Task_PowerMonit置位（Task未写，暂不可用）
SYSREADY_BIT_RC_LINK_OK      // Task_RC_Link置位（TODO，逻辑未接）
SYSREADY_BIT_IMU_HEALTH_OK   // Task_FlightCtrl置位，读g_imu_health
```

**Mutex/Semaphore**：不需要——每条总线/外设都被唯一Task独占访问。

**IWDG**：512ms超时（4095 reload, 4 prescaler）。喂狗权限只属于`Task_IwdgFeed`，其余Task只上报心跳时间戳到`g_heartbeat`，不直接调`HAL_IWDG_Refresh`。

**FreeRTOS关键配置**：
- `configTIMER_TASK_PRIORITY = 55`（跟`Task_FlightCtrl`打平，官方推荐Timer Task用最高优先级）
- `LIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 5`；EXTI4=6，EXTI15_10=5（不对称但都在安全范围内）
- `TICK_RATE_HZ = 1000`
- `TOTAL_HEAP_SIZE = 49152 Bytes`
- HAL Timebase用TIM6（不用SysTick，避免FreeRTOS接管SysTick后`HAL_GetTick`卡死）
- `DBG_IWDG_STOP`：CubeMX的SYS页面GUI里可能找不到，需手动在初始化阶段写`DBGMCU->APB1FZ |= DBGMCU_APB1_FZ_DBG_IWDG_STOP`（**未确认是否已加**）

## 三、分层与命名约定

- **alg层**（`alg_pid`/`alg_controller`/`alg_mixer`/`alg_attitude`）：纯数学，不碰HAL、不碰RTOS对象、不知道数据来自哪颗传感器。函数参数命名按物理意义取（如`roll_rate`而非`gx`），不暴露硬件相关命名。
- **bsp层**（`bsp_icm42688`/`bsp_qmc5883`/`bsp_gps`/`bsp_elrs`）：内部`static`存最新数据，对外只暴露`XXX_CopyTo(&out)`。传感器坐标系/贴装朝向的hack在这一层内部消化，不上抛。**该数据类型的定义归属生产它的bsp模块的头文件**（`IcmData_t`在`bsp_icm42688.h`，`MagData_t`在`bsp_qmc5883.h`，`RCChannelData_t`在`bsp_elrs.h`），不要放`app_shared_types.h`。
- **app层**（`app_flightctrl`/`app_nav`/`app_rc_link`/`app_iwdg_feed`）：任务编排、状态机、跨Task共享状态的实际存储。
- **`app_shared_types.h`只放两类东西**：(1) 没有唯一生产者、由某Task组装多来源拼出来的类型（如`NavState_t`）；(2) 真正跨Task共享的状态本体（`g_imu_health`、`g_heartbeat`）。不是"只要跨模块用就往这塞"。
- **模块内部私有的辅助结构体不进头文件**（如`bsp_qmc5883.c`内部的`MAG_Data_t`原始值容器，只在`.c`里`static`，不暴露）。
- **结构体传参不做强制类型转换，逐字段拷贝**——曾在`MagData_t`/`MAG_Data_t`混用踩过坑。
- Task内部延时用`osDelay`，不用`HAL_Delay`（阻塞式破坏调度）；`HAL_Delay`仅限调度器启动前使用。
- HAL弱函数回调（`HAL_GPIO_EXTI_Callback`、`HAL_UARTEx_RxEventCallback`）全工程仅一份实现，走专门dispatch文件按Pin/Instance分流。
- `freertos.c`里`StartTask_XXX`函数体只做一行转发调用（`App_XXX_Task(NULL)`），业务逻辑不写在这里；转发用`#include "app_xxx.h"`而非手写`extern`。

## 四、双IMU冗余（`app_imu2_redundancy.c`）

- ODR统一800Hz（ACC/GYRO），寄存器配置见下表。

| 寄存器 | 地址 | 值 | 含义 |
|---|---|---|---|
| ACC_RANGE | 0x41 | 0x03 | ±16G |
| ACC_CONF | 0x40 | 0x8B | 高性能, BWP=000, ODR=800Hz |
| GYR_RANGE | 0x43 | 0x00 | ±2000dps |
| GYR_CONF | 0x42 | 0xCB | 高性能+噪声优化, BWP=00, ODR=800Hz |
| INT_CFG1 | 0x06 | 0x03 | 推挽输出, 高有效, DRDY_GYR |
| PWR_CTRL | 0x7D | 0x0E | TEMP+ACC+GYR全开 |

- `ICM_InitAll()`里对两颗IMU都强制发起一次`ICM_ClearDataReadyLatch()`（burst读一次、只为清INT1锁存，不解析数据），打破"上电即锁存死锁"（芯片INT1是固定电平锁存型，写`INT_CFG1`生效瞬间若DRDY状态位已是1会直接锁死，EXTI永远等不到上升沿）。
- `Task_FlightCtrl`用`osEventFlagsWait(..., osFlagsWaitAny, 4ms超时)`等待任一IMU的DRDY。交叉比对、staleness检查**无条件每次循环执行**（不依赖两路DRDY同时到达，`osFlagsWaitAny`几乎不可能同时捕获两路独立时钟）。
- Staleness检查：`MAX_AGE_S = 3.0f / 800`，任一IMU数据龄期超过此值判定异常（防止"数据被冻结但数值巧合对得上"的盲区）。
- 六轴交叉比对阈值分开判断，取静止批稳健统计（median+4×MAD）与动态批P99的较大值：

```c
ACC_AX_DIFF_THRESHOLD_G    = 0.1005f
ACC_AY_DIFF_THRESHOLD_G    = 0.0244f
ACC_AZ_DIFF_THRESHOLD_G    = 0.0898f
GYRO_GX_DIFF_THRESHOLD_DPS = 1.9520f
GYRO_GY_DIFF_THRESHOLD_DPS = 2.5620f
GYRO_GZ_DIFF_THRESHOLD_DPS = 3.5990f
```

  **⚠️这批阈值仍是PROVISIONAL**——采集窗口跨越了IMU2从故障到修复的调试过程，尚未用完全修复的链路重新测过静止批+动态批。

- 切换策略（快切慢回）：连续5帧异常判定切走（`SWITCH_AWAY_THRESHOLD`），连续200帧健康判定切回（`SWITCH_BACK_THRESHOLD`）。
- **备用IMU的健康标志可以恢复，但不主动切回**——两颗物理对等，没有理由为切换而切换；只有当前active的一路自己触发`Health_RecordBad`时才检查备用是否可用。
- **双路失效处理**：`Health_RecordBad`触发切换前会先检查备用是否健康，不健康则冻结`active_imu_sel`不变，置起`g_imu_health.dual_fault`锁存标志，数据仍输出但下游需自行判断是否信任。`dual_fault`在`Health_RecordGood`里、当前active路持续正常时解除。**具体要不要因`dual_fault`触发额外保护动作尚未设计**，这一层只负责准确报告状态。
- 零偏补偿：切换瞬间不做offset淡出，接受可能的小抖动。
- 姿态融合状态（`Attitude_t`）在IMU切换时**保留、不重置**——两颗IMU物理朝向一致，切换只是数据来源换了。
- dt用`DWT->CYCCNT`实测，钳位±20%标称值兜底（防止调度异常帧污染PID）。

## 五、姿态融合与控制链

**分工**：`bsp_icm42688.c`在读取时完成ax/ay、gx/gy换轴（贴合IMU贴装朝向对齐NED），`alg_attitude.c`拿到的输入已经是这个约定下的坐标系，内部不再做任何朝向修正。

**pitch轴取负、roll轴不取负**这条规律，只在两处调用点生效，不进`alg_attitude`：
```c
AngleController_Update(fc.roll_target, fc.pitch_target, fc.roll_meas, -fc.pitch_meas, dt);
RateController_Update(..., active_data.gx, -active_data.gy, active_data.gz, dt);
```
`fc.pitch_meas`本身（黑匣子记录用的值）不取负，取负只发生在喂给控制器比较目标的那一刻。

**⚠️`Map_Pitch`当前实现丢了旧代码里的负号**（`(ch-991.5f)/819.5f*20.0f`，无前导负号），是否需要补回、还是跟上面两处负号之间确实存在需要保留的差异，**尚未做物理验证，悬而未决**。验证方法：不装桨状态下，手动倾斜机身对照`fc.pitch_meas`符号，单独验证摇杆方向对`fc.pitch_target`符号的影响，两者分开测，不要假设能互相抵消。

**控制链路顺序**（`Task_FlightCtrl`循环，800Hz）：
```
ImuRedundancy_Update → Attitude_ComputeAccelAngles/Attitude_Update
→（非阻塞取MagDataMailbox命中则）Attitude_CptYaw
→（非阻塞取RCChannelMailbox，未命中沿用上次值）
→ FlightControl_Update（RC映射+Yaw模式切换+角度环+角速度环+动态限幅）
→ Mixer → m1~m4
→ 【当前止步于此，未接DSHOT输出】
```

**Yaw控制**：手动模式（channel[5]>1500）直接`Map_Yaw`映射角速度目标，摇杆量小于5°/s视为0；否则Heading Hold模式，`YawHeadingHold_Update`用PID闭环锁定航向，模式切入瞬间锁定当前航向并清零积分。

**动态限幅**：`fc.throttle < 30`时持续调用`FlightControl_Reset()`（复位所有控制器和积分项，防止地面怠速积分饱和）；油门起来后，姿态修正量允许幅度按`fc.throttle - 30`动态放宽，上限250。

**RTH（自动返航）当前不接入**——旧代码本身标注"未经实机测试，严禁开启"，`Task_Nav`目前也不产出RTH所需的bearing/dist，等真正要做返航再补这条分支。

**倾角保护当前不接入**——已明确"先把控制链打通"，倾角保护待补。

## 六、ELRS/RC链路

- `bsp_elrs.c`：USART2 DMA循环接收，`ELRS_Poll`追赶DMA读写指针喂状态机组帧，CRC8校验通过后解析0x16（通道）/0x14（链路质量）帧。
- CRC8校验范围是`frame_buf[2]`到`frame_buf[frame_len-2]`（Type+Payload，不含Sync/Len），循环从`i=2`开始。
- 失联判定：`CRSF_FAILSAFE_TIMEOUT_MS = 70`（150Hz标称间隔6.67ms×10倍留裕量，**未做真实断链测试验证，数值待校准**）。
- `Task_RC_Link`轮询周期4ms（150Hz下留约3倍余量，DMA_BUF_SIZE=128字节可扛约2帧）。
- `ELRS_CopyTo`输出类型是`RCChannelData_t`（定义在`bsp_elrs.h`），跟`app_shared_types.h`里其他类型统一大小写风格，不要出现`RcChannelData_t`这种大小写变体。
- `RC_LINK_OK`这个EventGroup bit的置位逻辑**尚未接入**`Task_RC_Link`。

## 七、GPS/导航（`app_nav.c`）

- `Task_Nav`周期20ms，负责：处理`NavCommandQueue`命令、GPS轮询解析、组装`NavState_t`发`NavStateMailbox`、磁力计读取发`MagDataMailbox`。
- **开机自动搜星**：不依赖外部命令触发，主循环里每轮检查`s_home_valid`，未成功则持续重试`GPS_SetHome()`，成功后不再重试。`NavCommandQueue`保留给以后需要外部显式触发重新记录Home点的场景用。
- `GPS_SetHome()`成功条件：`gps_fix_type >= 1` 且 `gps_satellites >= 4`。
- 经纬度以`int32_t`定点整数存储（1e-7°单位），全程不经过float中间态，`NavState_t`赋值时**不做任何额外缩放**，直接赋值。

## 八、待办/未接项清单

按依赖关系排序：

1. **`bsp_dshot.c`未写**——是否内建arm闸门（旧代码`thr_to_dshot`内部读全局`arm_state`），还是由调用方显式传入解锁状态，未定案。`app_flightctrl.c`目前算完`m1~m4`后止步，未调用任何发送函数。
2. **ARM状态机未写**——依赖`Task_RC_Link`产出真实通道数据（已具备）；核心判据：`IS_ARMED`(channel[4]>=1000) + `Thr_LDet`(channel[2]<=180) + 倾角<30°；解锁后需锁定初始航向。落地判据：零油门+未解锁持续6秒确认停机。飞行中异常倾角/低电压需触发紧急disarm，但这两条分别依赖倾角保护（未接）和`Task_PowerMonit`（未写）。
3. **`Task_RC_Link`里`RC_LINK_OK`bit置位逻辑未接**。
4. **`Task_PowerMonit`未写**——`VOLTAGE_OK`bit无法产出，`SYSREADY_ARM_MASK`目前实际只有3/5位可用。
5. **交叉比对六轴阈值需要用完全修复的链路重新测**（静止批+动态批），当前数值是过渡期数据算出来的。
6. **`Task_Blackbox`未写**，`fc`结构体（体积较大）的撕裂读风险尚未处理，`FlightControl_CopyTo`目前是整体赋值，无临界区保护。
7. **`Map_Pitch`负号需要物理验证后才能定案**（见"五"）。
8. **倾角保护、RTH**暂缓，等控制链跑通后再接。
9. PLLQ、`DBG_IWDG_STOP`两项配置是否已在CubeMX里落实，未确认。
