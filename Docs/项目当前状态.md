# Alpha-Flight-2.X 当前状态

> 更新日期：2026-08-07  
> 依据：当前工作区源码、Blackbox日志004~112及本轮完整调试记录。若本文与早期《变更与踩坑记录》中的阶段性描述冲突，以本文和当前源码为准。

## 一、结论与当前边界

项目已经从“能转电机”推进到可柔和离地并完成较长时间低空飞行。临界油门左右振荡、Yaw闭环加速自旋、手动Yaw方向反转、active IMU旧帧被重复运行控制环等主要故障均已定位并修复。104/105/108/109显示手动与自动Yaw稳定性明显改善，Level Trim在静态数据中确实生效。

当前仍不是可直接扩大飞行包线的定稿版，以下高优先级边界尚未关闭：

1. 双IMU六轴交叉差值阈值仍为99.0G/99.9dps，等价于绕过数值一致性保护；当前只有通信、staleness、校准和active/standby调度层在提供保护。
2. `main.c`仍在`osKernelInitialize()`之前调用`osDelay()`完成DSHOT握手并直接喂IWDG，违反CMSIS-RTOS时序和单一喂狗职责，属于待清理脚手架。
3. CurrentLimiter当前明确关闭（`CURRENT_LIMITER_ENABLED=0`），只保留电流滤波和日志记录。

## 三、RTOS结构与共享机制

当前为7个业务Task加1个IWDG Task：

| Task | 优先级 | 主要职责 |
| --- | --- | --- |
| `Task_FlightCtrl` | Realtime7 | 双IMU、姿态、校准、ARM、串级PID、Mixer、DSHOT、控制日志 |
| `Task_RC_Link` | Realtime6 | CRSF DMA解析、RC校准、RC Mailbox与链路bit |
| `Task_Nav` | Realtime5 | GPS、QMC、Mag校正、I2C恢复、Nav/Mag Mailbox |
| `Task_Blackbox` | Realtime4 | FatFS文件生命周期、双缓冲写盘 |
| `Task_Telemetry` | Realtime4 | 预留，尚无业务实现 |
| `Task_PowerMonit` | Realtime4 | VBAT/电流、低压状态、限流数据 |
| `Task_Indicator` | Realtime4 | 蜂鸣器/LED节拍与优先级 |
| `Task_IwdgFeed` | Realtime4 | 根据心跳决定是否喂狗 |

双IMU冗余和ARM状态机不拆独立Task，均在FlightCtrl同一数据周期内执行，避免增加任务切换和跨Task时序误差。

Mailbox/Queue：`RCChannelMailbox`、`NavStateMailbox`、`MagDataMailbox`均为深度1覆盖式最新值；`IndicatorEventQueue`深度8；`NavCommandQueue`深度4。CMSIS-RTOS2无原生overwrite，统一采用“满则先Get旧值，再Put新值”。Blackbox不用Queue，使用双RAM缓冲和信号量。

FreeRTOS关键配置：抢占式调度、1kHz tick、heap 49152B、HAL timebase=TIM6、`LIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY=5`。调用RTOS API的EXTI/DMA/SPI ISR优先级必须保持数值不小于5，并使用`FromISR`接口。

## 四、SystemReady、ARM与校准互锁

当前解锁掩码为：

```c
MAG_OK | VOLTAGE_OK | RC_LINK_OK | IMU_HEALTH_OK |
RC_CALIB_OK | GYRO_CALIB_OK
```

`HOME_VALID`仍被Nav维护，但已经从ARM掩码移除，因为当前没有启用依赖GPS的飞行模式。`DEBUG_SKIP_ARM_READY_CHECK=0`，EventGroup检查实际生效。

Disarmed→Armed要求：曾真实看到ARM开关OFF、随后发生OFF→ON上升沿、油门低、Roll/Pitch均小于30°、全部ready bit满足、RC/Gyro校准完成，并且RC校准、Level Trim、Mag校准都不处于active状态。上电时ARM开关已在ON不会自动解锁；故障Disarm后开关仍在ON也不会自动re-arm。

Armed期间以下条件立即`Arm_ForceDisarm()`并在同一FlightCtrl周期发送四路DShot 0：人工ARM开关OFF、RC lost、双IMU故障、确认低压、任一轴65°立即倾倒，或超过50°持续100ms。当前无自动降落能力，因此RC lost采取Motor Kill语义。

`SYSREADY_BIT_xxx`只是bit位置常量；真正置位/清位由各Task调用`osEventFlagsSet/Clear`。二者是“选择哪一位”和“执行状态改变”的先后关系，不会重复冲突。

## 五、双IMU调度与上电Gyro校准

两颗ICM ACC/Gyro ODR均为800Hz。DRDY采用锁存型INT，初始化后必须完整burst读取一次清锁存；事件对象刚创建后不得再多做一次无条件clear，否则可能吞掉第一帧真实DRDY并造成永久等待。

`ImuRedundancy_Update()`由WaitAny唤醒，但只有active IMU产生新时间戳时才返回`IMU_UPDATE_ACTIVE_FRAME`并运行姿态/PID。standby新帧返回`IMU_UPDATE_STANDBY_ONLY`，只更新缓存和健康状态后`continue`。这修复了旧代码因两颗IMU轮流唤醒而重复消费active旧帧、控制频率接近1520Hz的问题。

`dt`由active IMU连续时间戳的DWT cycle差计算。有效范围0.5~5.0ms；`delta_cycle==0`或超范围返回时序异常，本帧跳过姿态/PID，只重建各PID微分采样基准；连续3次异常强制Disarm。正常800Hz约1.25ms，不再用固定±20%钳位后继续运行异常帧。

上电Gyro校准：每颗required IMU收集1600帧。`available_mask`表示初始化成功的硬件，`required_mask`表示本次必须完成的实例；两颗可用时均为0x03。静止门限为各轴绝对值≤3dps、Accel norm 0.85~1.15G；连续4帧非静止才重置累计，最终标准差必须≤0.40dps。校准期间持续发送DShot 0，`IMU_UPDATE_CALIBRATION`不会进入ARM与控制算法。

冗余切换仍采用快切慢回：连续5帧异常切走，健康200帧恢复备用健康标志，active连续健康50帧才清`dual_fault`。但六轴差值阈值当前为99.0/99.9的临时绕过值，正式飞行前仍需用装桨振动数据重新标定。

## 六、姿态、RC映射与控制器

控制链为：

```text
active IMU新帧 → Gyro校准偏置 → Accel角 → Level Trim
→ Roll/Pitch互补姿态 + YawEstimator
→ RC最新值 → Mag/Level Trim触发状态机 → Arm_Update
→ RC目标/Airmode/Yaw模式 → Angle P外环 → Rate PI内环
→ Current limit只缩放throttle → Mixer去饱和 → DSHOT
→ 每4帧写一条CONTROL V3
```

RC校准先处理原始CRSF，再将通道归一化到约172/992/1811及中心deadband。当前映射：Roll ±30°；Pitch带负号使摇杆前推对应低头；Yaw带负号使摇杆左移对应左旋；Throttle映射0~1152并做端点钳位。

当前PID：

| 环路 | P | I | D | 输出限幅 |
| --- | ---: | ---: | ---: | ---: |
| Angle Roll/Pitch | 2.5 | 0 | 0 | 250deg/s |
| Rate Roll/Pitch | 0.65 | 0.10 | 0 | 120 Mixer unit |
| Rate Yaw | 2.0 | 0.10 | 0 | 200 Mixer unit |
| Heading Hold外环 | 1.0 | 0 | 0 | 30deg/s |

这些参数已经比最初版本柔和并可离地，但尚不是10寸机的最终整定。Roll/Pitch漂移不等于Angle Hold失效：姿态角保持不能约束水平速度；数度以下的持续倾角、风、地效和推力不对称都会让位置越漂越远。

## 七、YawEstimator与Heading Hold

SA=`channels[5]`高位进入手动Yaw rate；低位为Heading Hold。退出手动模式时用当前融合Yaw重建`yaw_target`，清Yaw外环和Rate Yaw历史状态。

YawEstimator在每个active IMU帧用`gz`积分，在50Hz新Mag到达时做倾斜补偿并以0.02增益慢校正。基础门限：磁场0.05~2.0G、相对reference 0.65~1.35、Innovation±30°。Armed状态只允许通过门限的慢校正，绝不直接重置Yaw。

如果Mag长期被Innovation/field门限拒绝，Disarmed状态会尝试安全重新捕获：连续50个稳定样本，相邻Heading变化≤3°、相邻field ratio在0.9~1.1后，将Yaw、Mag yaw和field reference同步到新基准。FlightCtrl在Disarmed始终令`yaw_target=yaw_meas`，防止下次ARM产生旧目标跳变。

104/105/108/109表明自动Yaw抵抗效果明显改善，但不能保证百分百锁定。108中曾出现整段Mag被拒绝、实际主要靠Gyro的情况；因此Heading Hold增益不应在Mag校正尚未验证前继续激进提高。

## 八、Airmode、Mixer与DSHOT

Airmode采用油门迟滞：30启用，20以下退出。未启用时姿态控制器持续Reset，Mixer不允许用去饱和平移主动抬高collective；这消除了临界油门附近因低油门仍被整体抬到约1110而放大的左右振荡。当前注释明确这是近地测试策略，未来空中低油门是否退出应由airborne/landed状态决定，而不是只看油门。

Mixer输入为Roll/Pitch/Yaw修正、limited throttle和`airmode_enabled`。输出范围110~1352；先算四路差动，必要时按跨度等比例缩放，再做collective平移与最终clamp。Yaw Mixer符号已经按闭环响应修正；手动Yaw方向则在`Map_Yaw`修正，二者不能混改。

Armed发送`m1..m4 + 48`，即payload约158~1400；Disarmed持续发送纯0帧。DSHOT DMA buffer为`uint16_t`并显式放在`DMA_SAFE_SRAM`。此前TIM burst状态卡BUSY导致只发第一帧的问题已修复并通过持续运转验证。

仍需清理：`BSP_DSHOT_Init()`和3s零油门握手在Scheduler前运行，使用`osDelay`并直接喂IWDG。应迁回任务上下文，或在Scheduler前只使用HAL可用的时间基准，同时恢复只有`Task_IwdgFeed`喂狗。

## 九、RC校准、Failsafe与Level Trim

RC校准配置成功后写入Sector 11，后续上电直接加载，不必每次重做；更换接收机/遥控配置、端点明显变化或配置Flash被擦除时再重新校准。ELRS只允许CRC正确的0x16通道帧刷新`last_valid_frame_tick`，200ms无有效控制帧判失联。开机从未收到有效RC时`link_ok`保持false，但Indicator只有“曾连上后又断开”才报RC_LOST；持续失联每2500ms重报。

Level Trim使用SE（CH7/`channels[6]`）长按3s触发，要求Disarmed、ARM OFF、低油门。每颗required IMU收集1600帧Accel角，静止门限3dps与0.85~1.15G，采样角不超过10°，最终Roll/Pitch标准差不超过0.75°。成功后写Flash并等待滤波稳定1s。Trim只减去Accel Roll/Pitch偏差，不修改Gyro、最终姿态或Yaw。

109静态数据已经证明Trim偏置被加载并生效；飞行仍缓慢漂移主要是没有Velocity Hold，而非继续重复做Trim即可解决。

## 十、配置Flash与烧录规则

Sector 11（`0x080E0000..0x080FFFFF`）保留给追加式配置记录。每个slot 64B，payload最大40B，带record type、version、sequence和CRC。RC Calibration使用record type 0x0001，Level Trim使用0x0002。

`CubeMX_Create.sct`把Firmware load/execution region限制为0xE0000，避免链接到Sector 11。Keil Flash Download必须选`Erase Sectors`，不能选`Erase Full Chip`，否则已保存校准会被擦除。

当前`CubeMX_Create.uvprojx`的Target设置仍将IROM size显示为0x100000，而自定义scatter实际使用0xE0000。由于链接器已显式使用scatter，当前产物不会占Sector 11；但仍应把Target显示同步改为0xE0000，防止未来误启用自动Memory Layout时产生回归。

## 十一、Mag、I2C与Hard/Soft-Iron

Nav每20ms读取QMC。只有`QMC_ReadData()==HAL_OK`才复制、校正并发布新Mag；失败时清`MAG_OK`，不再重复发布BSP旧缓存。连续3次失败触发`IIC_RecoverBus()`：DeInit、PB6/PB7开漏释放、最多9个SCL脉冲、手工STOP、重新初始化I2C，成功后再次`QMC_Init()`，必须等下一帧真实成功才置`MAG_OK`。

I2C1已从400kHz降至100kHz Standard Mode。DSHOT启用时400kHz曾出现分散的HAL_BUSY/SDA低故障；100kHz测试约18474次读取无错误。QMC仅50Hz，降低总线速率对系统吞吐影响可忽略。Bus recovery作为正式容错保留。

Hard/Soft-Iron采集使用SB（CH8/`channels[7]`）：中档待命/正常结束，高档保持3s开始，低档取消；至少1500帧，最多8000帧。采集写独立Blackbox文件，记录校正前的NED Gauss向量。采集期间锁Arm。

112室外标定是当前选定参数：

```text
bias = { 0.777633692, -1.131458540, 0.921689385 } G
soft symmetric = {
  1.012112088,  0.024130066,  0.006713267,
  0.985058770, -0.005159549,  1.007059819
}
field reference = 0.458847875 G
```

校正公式为`corrected = A * (raw_ned - bias)`，A按对称六参数存储。Nav中的正确顺序必须是：复制原始NED→记录校准样本→应用校正→发布。

`MagCalibration_Apply()`当前已按三轴独立输入实现：

```c
const float x = mag->MX - bias[0];
const float y = mag->MY - bias[1];
const float z = mag->MZ - bias[2];
```

该实现已与当前源码核对一致，112室外拟合参数已经接入运行时校正链。下一步仍应先在Disarmed状态验证校正后的三轴模长、Innovation和Mag accepted比例，再做户外小范围飞行。Hard/Soft-Iron只解决固定机载磁偏；电流/油门相关动态磁偏模型已明确延期。

## 十二、Blackbox与离线工具

记录格式统一为`[0xAA magic][type][payload]`，小端。当前类型：0x01 MOTION、0x02 ARM_CHANGED、0x03 DUAL_FAULT、0x04 VOLTAGE_FAULT、0x05 IMU_SWITCH、0x06 CONTROL V1、0x07 V2、0x08 V3、0x09 MAG_CAL_SAMPLE。固件FlightCtrl当前只写0x08控制帧；0x06/0x07为旧日志兼容。

CONTROL V3总长85B、约200Hz，包含DWT时间戳、姿态/目标、Level Trim、Mag yaw/Innovation/field、Rate target/measured、三轴PID P/I/D/output、四电机、原始/受限油门、dt、active/fresh IMU、Current与状态flags。双缓冲为4096B×2，位于DMA可访问SRAM，约可吸收560ms短时写盘停顿。

文件通常由Arm边沿懒加载：Armed请求开新文件，Disarmed请求flush/close。Mag校准可在Disarmed请求独立文件，并通过`IsFileOpen`/`LastCloseSucceeded`握手。已知缺陷是`BB_Init()`失败后每500ms无限重试；Mag WAIT_FILE_OPEN无法超时退出，会持续锁Arm。应增加可取消/超时的文件打开结果。

`BB_WriteBytes`在跨缓冲Publish失败时回滚本记录，避免半帧。尚未给多个生产者加完整互斥；当前只允许Control高频，其余事件低频，以不阻塞FlightCtrl为优先。若CSV出现非0 `resync_count`，仍要把生产者竞态作为调查对象。

Python工具：`D:\Project\Python\SD_RC_PARSE\main.py`支持全类型解析、默认20条预览、`--print-all`、`--csv`完整导出和专项图；`mag_cal_fit.py`负责0x09样本椭球拟合、outlier处理和质量统计。

## 十三、电源、SD与DMA内存安全

PowerMonitor周期20ms。VBAT≤13.2V连续25次（约500ms）置`voltage_fault`并清ready bit，≥13.5V恢复；14.0V为只报警不动作的低压预警，14.2V解除其迟滞。一次飞行末尾13.75V停机与长时间飞行、电压下降一致，不是未知控制器停机。

CurrentLimiter设计参数仍保留：44A阈值、0.10s电流LPF、0.15s attack、1.0s release、最低60% throttle；但当前宏为0，FlightCtrl收到1000‰，只记录滤波电流。ADC Poll已改有限超时，但仍应补返回值检查，失败时不能用无效寄存器值覆盖缓存。

SD DMA约10s卡顿的根因已确认并修复：scratch buffer曾被链接到0x10000000 CCM，DMA物理不可访问。当前scatter规则为普通RW/ZI默认落SRAM1，CCM只允许显式opt-in；`s_sdTxDummy`、`s_sdRxSink`、`s_dshot_buf`以及当前Blackbox缓冲均显式位于`DMA_SAFE_SRAM`。

FatFS仍有一个CubeMX生成风险：`diskio.c`中只有真正初始化成功才置`is_initialized`的补丁位于中间件文件，重新生成代码可能覆盖，生成后必须复查。SD命令重试需要真实延时，不能用紧密循环代替卡内部恢复时间。

## 十四、GPS、Position/Velocity与未实现功能

Nav持续GPS解析并尝试记录Home，经纬度使用1e-7°的`int32_t`，不经过float缩放。`HOME_VALID`当前不阻止Arm。RTH仍未实现，旧方案未经实飞验证，不应提前启用。

没有气压计仍可做水平速度/位置控制：GPS提供低频地速/位置，IMU提供高频短期动态，后续架构应为GPS+IMU水平StateEstimator→Position P生成Velocity目标→Velocity PI生成Roll/Pitch目标。垂直方向没有可靠高度源，暂时保持人工油门；当前低高度弹跳不能靠水平Velocity Hold解决。

实现顺序仍是：先修正并验证Mag校正和Heading Hold，再做水平Velocity Hold，最后才考虑Position Hold/RTH。ESC KISS Telemetry（UART5 RX、四路round-robin）只有设计，代码未实现。

## 十五、提示系统与调试规则

Indicator把事件队列转换为LED/蜂鸣器节拍，并按NOTICE、WARNING、POWER_LIMIT、CRITICAL、STATE_CHANGE抢占。RC lost、Critical battery、IMU fault与Current limiting支持周期重报；ARM/DISARM等状态沿只报一次。生产/消费两侧尚无统一同事件去重，深度8队列在多故障持续时仍可能被重复事件填满；低压与Critical battery也尚未互斥。

注释规范：公共API在`.h`用`/** ... */`说明契约；`.c`中的static helper需要时也可用Doxygen风格，但普通实现原因优先用`/* ... */`或`//`。`/** */`不是“只能给函数”，它的关键语义是希望被文档工具识别；不要给每一行普通代码都套文档注释。

实时电机测试禁止依赖断点。CPU Halt会让RTOS、PID和发送节奏冻结，而DMA/外设/ESC的物理状态未必同步进入安全态。调试控制问题应拆桨、必要时关闭DSHOT，并用SD低频诊断记录；不要为了记录而临时破坏Arm、Level Trim或Mag校准的前置条件。
