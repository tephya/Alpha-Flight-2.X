# Alpha-Flight-2.X 项目当前状态

> 更新日期：2026-08-25  
> 依据：当前工作区源码、Blackbox 日志 004～318、现有构建配置与已完成的实测记录。若本文与《变更与踩坑记录》中的阶段性描述冲突，以本文和当前源码为准。

## 一、总体结论

基础姿态控制链已经达到可飞状态。起飞临界油门附近的 Roll/Pitch 振荡、Yaw 闭环正反馈自旋、手动 Yaw 方向反转、active IMU 旧帧被重复送入控制环等阻断飞行的问题已经修复；Hard/Soft-Iron 校正投入后，Heading Hold 的持续抵抗和自动回正能力也明显优于早期版本。

水平导航闭环已经完成代码和实飞链路打通：GPS 与 IMU 进入 Horizontal Estimator，Position 外环生成 Velocity Target，Velocity PID 生成 Roll/Pitch Target，再进入原有 Angle→Rate→Mixer 控制链。SC 中档为 Velocity Hold，高档为 Position Hold，低档为 Manual。

当前 Position Hold 仍不能视为可靠定点功能。多轮户外测试反复出现以下现象：松杆后慢漂或越漂越快、抗风响应偏弱或偏迟、偶发机身突然压向一侧并快速位移。飞手持续小幅修正时可在较小范围内悬停，但无人干预时结果受风、卫星数量、HDOP、低速 GPS 方向噪声及控制状态历史影响明显。

日志 303 曾表现较好，但按同一版本复测后并未稳定复现，说明 303 不能作为已验证的“最佳版本”；当时的环境和 GPS 质量很可能贡献了较大影响。当前保留最后一轮结构性修改，但实测没有证明它带来明确改善。本阶段优化暂时结束，不再把单次观感作为算法收敛证据。

## 二、当前高优先级边界

1. Position Hold 已实现但尚未达到可放手依赖的可靠性，不能据此扩大飞行包线或启用 RTH。
2. 当前只有单 GPS，没有 Optical Flow、RTK 或其他低速水平速度基准；Position-window Velocity 与 RMC 来自同一模块，只能交叉检查计算路径，不能当作独立冗余传感器。
3. 气压计损坏，垂直方向仍由飞手直接控制 Throttle；没有 Altitude Hold、Vertical Velocity Hold 或自动降落能力。
4. 双 IMU 六轴交叉差值门限仍为 99.0 G/99.9 dps，等价于暂时绕过数值一致性保护；通信、staleness、校准和 active/standby 调度保护仍在工作。
5. `main.c` 仍在 `osKernelInitialize()` 前调用 `osDelay()`完成 DSHOT 握手并直接喂 IWDG，属于待清理的启动脚手架。
6. `CURRENT_LIMITER_ENABLED=0`，CurrentLimiter 当前关闭，只保留电流滤波与日志数据。
7. 配置 Flash 依赖 scatter 文件把 Firmware 限制在前 0xE0000；Keil Target 中 IROM 显示值仍为 0x100000，应在后续工程整理时统一。

## 四、RTOS 结构与共享机制

当前为 7 个业务 Task 加 1 个 IWDG Task：

| Task | 优先级 | Stack | 主要职责 |
| --- | --- | ---: | --- |
| `Task_FlightCtrl` | Realtime7 | 2048 B | 双 IMU、姿态、校准、ARM、水平估计、串级控制、Mixer、DSHOT、控制日志 |
| `Task_RC_Link` | Realtime6 | 1024 B | CRSF DMA 解析、RC 校准、RC Mailbox 与链路 bit |
| `Task_Nav` | Realtime5 | 1536 B | GPS、QMC、Mag 校正、I2C 恢复、Nav/Mag Mailbox |
| `Task_Blackbox` | Realtime4 | 2048 B | FatFS 文件生命周期与双缓冲写盘 |
| `Task_Telemetry` | Realtime4 | 1024 B | 预留，尚无业务实现 |
| `Task_PowerMonit` | Realtime4 | 640 B | VBAT/电流、低压状态、限流数据 |
| `Task_Indicator` | Realtime4 | 512 B | 蜂鸣器/LED 节拍与优先级 |
| `Task_IwdgFeed` | Realtime4 | 512 B | 根据各 Task 心跳决定是否喂狗 |

双 IMU 冗余和 ARM 状态机位于 FlightCtrl 同一数据周期。`RCChannelMailbox`、`NavStateMailbox`、`MagDataMailbox`均为深度 1 的最新值 Mailbox；`IndicatorEventQueue`深度 8；`NavCommandQueue`深度 4。Blackbox 不走 Queue，采用双 RAM 缓冲与信号量。

FreeRTOS 为抢占式调度、1 kHz tick、heap 49152 B，HAL timebase 使用 TIM6。调用 RTOS API 的 ISR 必须满足 FreeRTOS 中断优先级约束并使用 `FromISR` 接口。

## 五、SystemReady、ARM 与安全链

当前解锁掩码为：

```c
MAG_OK | VOLTAGE_OK | RC_LINK_OK | IMU_HEALTH_OK |
RC_CALIB_OK | GYRO_CALIB_OK
```

`HOME_VALID`仍由 Nav 维护，但不属于基础解锁条件；Manual Flight 不依赖 GPS。Disarmed→Armed 要求真实观察到 ARM OFF 后的 OFF→ON 上升沿、低油门、Roll/Pitch 小于 30°、全部 ready bit 满足，并且 RC Calibration、Level Trim、Mag Calibration 均不处于 active 状态。

Armed 期间遇到人工 ARM OFF、RC lost、双 IMU 故障、确认低压或倾倒保护触发，会在 FlightCtrl 周期内强制 Disarm 并发送四路 DSHOT 0。系统没有自动降落能力，因此 RC lost 仍采用 Motor Kill 语义。

水平辅助模式另有独立进入条件，不写入基础 ARM 掩码：必须先真实经过 SC Manual 档，再出现新的模式切换沿；Estimator 健康、Throttle≥400、GPS Velocity 连续接受至少 3 帧且 Estimator 与观测一致。Position Hold 还要求 GPS Position ready、连续接受至少 3 帧、Position Innovation 一致。条件失效后立即退回 Manual，不能在条件恢复时自动接管，飞手必须重新拨回 Manual 再进入。

## 六、双 IMU、Gyro Calibration 与控制周期

两颗 ICM 的 Accel/Gyro ODR 均为 800 Hz。只有 active IMU 的新时间戳返回 `IMU_UPDATE_ACTIVE_FRAME`并运行姿态与控制；standby 新帧只更新缓存和健康状态，防止同一 active 旧帧被重复消费。

控制 `dt`来自 active IMU 连续 DWT cycle 差。有效范围 0.5～5.0 ms；`delta_cycle==0`或超范围时跳过本帧姿态/PID，只重建 Derivative 历史，连续 3 次异常强制 Disarm。

上电 Gyro Calibration 对每颗 required IMU 收集 1600 帧。静止门限为各轴绝对值≤3 dps、Accel norm 0.85～1.15 G；连续 4 帧非静止才清空累计，最终各轴标准差必须≤0.40 dps。校准期间持续发送 DSHOT 0，不运行 ARM 与飞行控制。

冗余切换采用快切慢回：连续 5 帧异常切走，健康 200 帧恢复 standby healthy，active 连续健康 50 帧才清 dual fault。六轴数值差门限仍待使用装桨振动数据重新标定。

## 七、姿态、Yaw 与控制器

当前完整控制链为：

```text
active IMU 新帧
→ Gyro Bias / Level Trim / Roll-Pitch Attitude / YawEstimator
→ Horizontal Estimator 与水平模式状态机
→ Angle Controller
→ Rate Controller + Roll/Pitch Rate Feedforward
→ Mixer 去饱和
→ DSHOT
```

主要参数：

| 环路 | P | I | D | 输出限幅 |
| --- | ---: | ---: | ---: | ---: |
| Angle Roll | 4.20 | 0 | 0 | 250 deg/s |
| Angle Pitch | 4.20 | 0 | 0 | 250 deg/s |
| Rate Roll | 1.30 | 0.10 | 0 | 120 Mixer unit |
| Rate Pitch | 1.25 | 0.10 | 0 | 120 Mixer unit |
| Rate Yaw | 2.00 | 0.15 | 0 | 200 Mixer unit |
| Heading Hold 外环 | 1.00 | 0 | 0 | 30 deg/s |

Roll/Pitch Rate Feedforward 分别为 0.50/0.40，输出限幅 10。Yaw Rate Integral 在目标角速度 5 dps 以下正常增长，5～20 dps 逐步放松，20 dps 以上禁止继续增长但允许已有 Integral 卸载，降低大 Yaw 机动结束后的过冲。

SA=`channels[5]`高位进入 Manual Yaw Rate，低位为 Heading Hold。YawEstimator 每个 active IMU 帧用 `gz`积分，50 Hz 新 Mag 到达时做倾斜补偿并以 0.02 增益慢校正。Mag 门限为绝对场强 0.05～2.0 G、相对 reference 0.65～1.35、Innovation ±30°。

Armed 时异常 Mag 只拒绝，不允许重置 Yaw；Disarmed 时可用连续 50 个稳定样本执行安全 Reacquire。正常通过门限时，Disarmed 还允许 field reference 以 0.02 增益跟踪长期环境变化。114/115、119 及后续测试说明 Heading Hold 已能持续抵抗并自动拉回小幅偏航，但不等于绝对无漂移。

## 八、Mag、I2C 与 Hard/Soft-Iron

Nav 每 20 ms 读取 QMC。只有 `QMC_ReadData()==HAL_OK`才复制、校正并发布新 Mag；失败时清 `MAG_OK`，不重复发布旧缓存。连续 3 次失败触发 `IIC_RecoverBus()`：DeInit、PB6/PB7 开漏释放、最多 9 个 SCL 脉冲、手工 STOP、重新初始化 I2C，再重新配置 QMC。恢复后必须等下一帧真实读取成功才重新置位 `MAG_OK`。

I2C1 已由 400 kHz 降至 100 kHz Standard Mode。DSHOT 开启时 400 kHz 曾出现分散的 HAL_BUSY/SDA 低故障；100 kHz 长时间读取测试稳定。Bus recovery 作为正式容错保留。

当前运行时 Hard/Soft-Iron 参数来自后续户外数据重新拟合：

```text
bias = {
   0.769966473,
  -1.132992138,
   0.907445057
} G

soft symmetric = {
  1.007267649, 0.029346188, 0.008633474,
  0.990599558, 0.004140657, 1.003350263
}

field reference = 0.473539573 G
```

校正公式为 `corrected = A * (raw_ned - bias)`。正确数据顺序为：QMC 原始数据完成 NED 轴变换→必要时记录 Mag Calibration 样本→应用 Hard/Soft-Iron→发布 Mailbox。Hard/Soft-Iron 只补偿固定于机体的静态磁偏和轴间缩放/耦合，不能消除随电流、油门或外部环境动态变化的磁干扰；电流/油门—Mag Bias 模型继续延期。

## 九、Airmode、Mixer、DSHOT 与电源

Airmode 使用 30 启用、20 以下退出的 Throttle 迟滞。未启用时姿态控制器持续 Reset，Mixer 不允许通过去饱和平移主动抬高 collective。这一策略消除了临界油门附近四电机被整体推高所放大的 Roll 振荡。未来若完善 airborne/landed 判定，应由飞行状态决定空中低油门行为，而不是仅依赖 Throttle。

Mixer 输出范围 110～1352，先计算四路差动，必要时按跨度等比例缩放，再做 collective 平移与最终 clamp。Armed 发送 `motor + 48`，Disarmed 持续发送纯 0。DSHOT DMA Buffer 位于 DMA 可访问 SRAM。

PowerMonitor 周期 20 ms。VBAT≤13.2 V 连续约 500 ms 触发低压 Disarm，≥13.5 V 恢复；14.0 V 为只报警不动作的预警。CurrentLimiter 设计保留，但当前关闭，FlightCtrl 始终收到 1000‰ scale。

## 十、GPS 与水平 StateEstimator

GPS 上电后等待 2 s，在 9600 与 115200 两种波特率路径上发送配置命令，目标运行配置为 115200、仅输出 GGA/RMC、10 Hz。系统以连续 10 个 RMC 周期的平均值 70～140 ms 验证配置是否生效；连续两个异常窗口、2 s 无 RMC 或 4 s 未完成验证会请求重配。UART Abort/Re-init/DMA Restart 只允许在 Disarmed 执行。

Nav Task 以 50 Hz 运行，但只有新的 RMC Sequence 才产生新 GPS Velocity Sample。Velocity Control 基础门限为卫星数≥8、HDOP≤2.5、RMC 周期≤400 ms、RMC age≤600 ms、GGA age≤1500 ms。Position Hold 使用更严格门限：卫星数≥12、HDOP≤2.0。

Horizontal Estimator 在每个 active IMU 周期执行水平 Acceleration 预测，在新 GPS 样本到达时融合 Velocity 与 Position：

```text
IMU Acceleration + Attitude/Yaw
→ Body 到 N/E 投影、5 Hz LPF、Bias 扣除
→ Velocity/Position 高频预测
→ RMC Velocity Correction
→ GPS Position alpha-beta Correction
```

Estimator 的离散融合增益仍以原 5 Hz 参数为参考，但按实际 GPS sample dt 换算等效增益，避免 5 Hz→10 Hz 后单位时间修正带宽翻倍。单帧 Velocity 状态修正按最大 2.0 m/s² 限速，Position 单帧状态修正上限 0.12 m，防止长 GPS 间隔后的单帧突变。

低速时 RMC Ground Speed 尚可参考，但 Course 方向不可靠；低于 0.25 m/s 时不直接采用其 N/E 方向。Position-window Velocity 使用最近约 0.4～0.7 s 的位置样本做线性回归，主要用于与 RMC 做一致性检查、BRAKING 判定和日志诊断；当前控制主观测仍固定为 RMC。

Accel Bias 以机体 Forward/Right 保存，再随 Yaw 投影到 N/E。Disarmed 静止学习要求 GPS speed<0.15 m/s、Gyro 各轴<3 dps、Accel norm 0.85～1.15 G 并持续 1 s。飞行中的慢修正只允许在 Position Hold 已稳定进入 HOLD、两种 GPS Velocity Observation 一致且等待 1 s 后执行，避免把真实机动或 GPS 瞬态学成 IMU Bias。

## 十一、Velocity Hold 与 Position Hold

SC=`channels[8]`（CRSF CH9）：低档 Manual，中档 Velocity Hold，高档 Position Hold。水平摇杆使用 2° Deadzone、0.50 Expo 和 6 m/s²二维命令变化率限制；Velocity Hold 最大 Pilot Velocity 2.0 m/s，Position Hold 为 1.5 m/s。模式接管在 0.5 s 内平滑混入导航 Roll/Pitch Target。

Velocity Controller 为 N/E PID：`Kp=1.80`、`Ki=0.50`、`Kd=0.20`。Integral Acceleration 限幅 0.80 m/s²，总 Acceleration Target 限幅 2.00 m/s²、Slew 8.00 m/s³，最终 Roll/Pitch Target 限幅 12°。D 项使用实测水平 Acceleration 提供阻尼。

Position Controller 为 P 外环：`Kp=0.70`，Deadband 0.10 m，输出二维 Velocity Target 最大 1.20 m/s。状态机为：

```text
INACTIVE → MOVING → BRAKING → HOLD
```

Pilot 有输入时进入 MOVING；松杆后进入 BRAKING。只有 Estimator 与两种 GPS 速度观测均表明低速，并连续取得足够新样本，才捕获新的 Hold Anchor，禁止仅靠超时把仍在运动的位置锁为目标点。

Velocity Integral 在 Position Hold 中分三种模式：MOVING/BRAKING 为 `FROZEN`；HOLD 但学习条件未连续满足时为 `UNLOAD_ONLY`；接近 Anchor、速度较小、GPS 连续有效达到门限后才进入 `LEARN`。Velocity Hold 则允许正常学习。Velocity↔Position 直接切换保留已有 Integral；Manual→辅助模式从干净的 Controller 状态开始。

上述结构解决了多项确定性问题，包括低速 RMC Course 乱向、延迟 GPS 单帧获得过大修正权、BRAKING 过早捕获 Anchor、人工移动阶段积累迟到 Integral、模式切换时静态补偿突变等。它改善了部分测试中的突然冲出和可拉回性，但没有证明能够在当前传感器条件下稳定抗风定点。

## 十二、Blackbox 与离线工具

记录统一为 `[0xAA magic][type][payload]`小端格式。当前类型：

| Type | Record |
| ---: | --- |
| 0x01～0x05 | Motion 与基础事件 |
| 0x06～0x08 | 旧 Control V1～V3，保留解析兼容 |
| 0x09 | Mag Calibration Sample |
| 0x0A | 当前 Control V4 |
| 0x0B～0x0E | 旧 Navigation V1～V4，保留解析兼容 |
| 0x0F | 当前 Navigation V5 |

Control V4 总长 90 B，约 200 Hz；包含姿态/目标、Level Trim、Mag Yaw/Innovation/field/reject reason、Rate Target/Measurement、PID P/I/D/Output、Motor、Current、Throttle、dt、active/fresh IMU 与状态 flags。

Navigation V5 总长 76 B，约 20 Hz；包含 RMC Sequence、GPS/Estimator Velocity、Acceleration/Bias、Velocity Target、Navigation Roll/Pitch Target、Velocity Integral、GPS age/period/HDOP/satellites、Estimator Position、GPS Position、Position Target/Error、RMC 与 Position-window Velocity、Horizontal Mode 和 Position Phase。

Blackbox 采用 4096 B×2 双缓冲并放在 DMA-safe SRAM。文件通常由 ARM 边沿异步创建/关闭；Mag Calibration 可在 Disarmed 创建独立文件。多个生产者尚无完整互斥，当前策略仍是 Control/Navigation 高频、其他事件低频，并优先保证 FlightCtrl 不被 SD I/O 阻塞。

`D:\Project\Python\SD_RC_PARSE\main.py`已同步解析 Control V4 与 Navigation V5，支持完整 CSV 导出和控制/导航专项图。修改 Firmware Record Layout 时必须同步更新 Python `REC_SPECS`、字段单位和版本兼容逻辑。

## 十三、配置 Flash、SD 与 DMA 安全

Sector 11（`0x080E0000..0x080FFFFF`）用于追加式配置记录。每个 Slot 64 B、Payload 最大 40 B，带 type、version、sequence 与 CRC。RC Calibration 使用 type 0x0001，Level Trim 使用 type 0x0002。

Keil Flash Download 必须选择 `Erase Sectors`，不能使用 `Erase Full Chip`，否则已保存校准会被擦除。当前 scatter 文件将 Firmware 区限制为 0xE0000，但 Keil Target 显示值仍应同步修正。

SD DMA 长时间卡顿的根因曾是 Buffer 被链接到 DMA 不可访问的 CCM。当前普通 RW/ZI 默认落 SRAM1，DMA Buffer 显式放入 `DMA_SAFE_SRAM`；CCM 只允许明确 opt-in。重新生成 CubeMX 后仍需复查 FatFS `diskio.c`中的初始化补丁，避免生成代码覆盖。

## 十六、后续恢复本方向时的原则

本阶段暂停后，不应继续仅凭一次主观观感修改多组增益。恢复 Position Hold 调试时，应先固定机体、电池、场地、风况和 GPS 门限，设计可重复的动作段，并在日志中明确区分 Pilot Active、BRAKING、HOLD 与模式切换。

优先分析以下量的时间关系：GPS/RMC/Position-window 原始观测、Estimator 状态、Position Error、Velocity Target、P/I/D Acceleration、Navigation Roll/Pitch Target、实际姿态和 RC 输入。只有同一现象在多次相近条件下重复出现，才将其作为结构或参数修改依据。

如果目标是显著提高低速定点可靠性，优先级高于继续堆叠补丁的是：提高水平低速观测质量，或增加与 GPS 独立的近地速度/位置来源。单 GPS 架构仍可继续优化，但不能把环境相关的单次成功等同于完成定点能力。

其他仍需保留的工程任务：清理 Scheduler 前 DSHOT/IWDG 脚手架、恢复双 IMU 正式交叉门限、统一 IROM 配置、完善 Blackbox 文件打开失败的超时/取消路径，并继续保持实时电机测试禁用断点。
